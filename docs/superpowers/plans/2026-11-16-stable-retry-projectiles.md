> **For agentic workers:** Use superpowers:executing-plans and test-driven-development. The user has already requested direct execution without further design questions.

**Goal:** Restart without moving the page up/down; give projectile objects readable internal animation.

**Architecture:** Keep the existing Canvas game and DOM. Limit automatic page alignment to the first start when the arena needs it. Animate individual weapon pieces in the existing vector renderer and preserve all physical projectile paths/hitboxes.

**Tech Stack:** JavaScript, Canvas2D, Node test runner, Playwright and native Canvas.

## Global constraints

- No physics, boss hierarchy, ammo, damage or difficulty changes.
- Preserve manual page scrolling and first-start access on short screens.
- Respect reduced motion and pause; no new image atlas or dependencies needed.
- Changes are independent: page-layout/runner retry handling vs weapon object renderer. Root owns shared asset version updates.

## Review focus

- Actual mouse/touch retry can scroll before its click when a focused control moves in the DOM.
- Repeated death/retry must not progressively shift arena geometry or document scroll.
- Keyboard/controller and automatic prison retry use the same behavior.
- Short landscape screens still show the arena and accessible retry controls.
- Projectile animation must move object parts, not merely particles or a whole static sprite, and remain inside readable bounds.
